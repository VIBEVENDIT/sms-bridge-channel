# 자동회신·triage 정책

이 앱은 자유 생성형 답변을 만들지 않는다. 운영 중 확인된 호텔 정책만 정해진
문구로 답하고, 그 밖의 질문은 안전한 접수 문구만 보낸다. 예약·금전·안전 판단은
항상 `#lounge-호텔앳강남`의 사람이 처리한다.

## 조사 근거

- 이 저장소의 기존 `main`은 Windows updater feed뿐이었고 자동회신 코드는 없었다.
- 접근 가능한 관련 저장소 `VIBEVENDIT/pms.hoteliers.space`도 검색했으나 호텔메일
  자동회신 구현은 발견되지 않았다.
- 실제 lounge의 호텔메일 triage는 `*[메일수신]* :완료:`와 `:완료:` 상태를 사용한다.
  SMS도 같은 형태인 `*[문자수신]*` 및 `:완료:`를 사용한다.
- lounge의 실제 처리 기록에서 반복 확인된 정적 정책만 FAQ에 포함했다:
  1층 셀프 짐 보관, 심야 1층 키오스크 셀프 체크인, 1층 라운지 카페 21시까지.

호텔 정책이 바뀌면 `HotelReplyPolicy`의 문구와 해당 테스트를 같은 PR에서
수정해야 한다.

## 판정 순서

1. **절대 회신 제외**
   - OTP/인증번호/verification code
   - `(광고)`, `[광고]`, 무료수신거부, `080-`, unsubscribe 표식
   - `noreply`, `do not reply`, 발신 전용, 회신 불가, 자동 발송 문자
   - `STOP`, 수신거부
   - `네`, `확인했습니다`, `감사합니다`, `OK` 같은 단순 확인
2. **사람 확인**
   - 예약 변경·취소, 환불·결제·청구
   - 객실/침대/성별 변경
   - 불만·보상, 사고·응급·경찰, 분실·도난
   - 질문인지 확실하지 않은 서술
3. **검증된 FAQ 자동회신**
   - 짐/수하물 보관
   - 심야 도착/늦은 체크인
   - 라운지·음식 공간 이용시간
4. **그 밖의 명확한 질문**
   - 앱 설정의 안전한 접수 문구로만 회신한다.
   - 기본값은 “확인 후 답변”이며 사실·가격·재고를 추측하지 않는다.

발신번호가 국제번호(`+…`) 또는 국내 휴대전화 번호가 아니면 자동회신하지 않는다.
다만 원문은 lounge에 남겨 사람이 판단할 수 있다.

## 중복·루프·스팸 방지

- Android SMS fingerprint(발신번호, 본문, 통신사 timestamp, SIM ID)를 7일 보관한다.
- Slack `event_id`를 7일 보관하고 Socket Mode envelope는 로컬 DB 저장 후에만 ACK한다.
- 같은 수신 이벤트는 로컬 SQLite 큐의 primary key로도 중복 저장되지 않는다.
- Slack 게시 실패 시 이벤트는 큐에 남고 재시도하며, 이때 SMS 자동회신은 보내지 않는다.
- 최근 5분 내 동일 번호로 보낸 동일 본문이 다시 들어오면 echo로 간주한다.
- 자동회신 본문 자체가 되돌아오면 회신하지 않는다.
- 발신자별 cooldown, 자동회신 시간당 한도, 전체 SMS 시간당 한도를 전송 전에
  영구 예약한다.
- SMS는 Android가 모든 multipart 조각의 `RESULT_OK`를 반환한 뒤에만 Slack에
  `:완료:`를 기록한다.
- 불확실한 모뎀 실패는 자동 재발신하지 않는다. 중복 과금보다 사람이 새 명령을
  보내는 at-most-once 정책을 우선한다.

## Slack triage

수신 root:

```text
*[문자수신]*
*발신번호* = `010…`
*수신일시* = 2026-10-07 12:34:56 KST
*문의내용* = …
*분류* = 자동회신 예정 · 짐보관 FAQ
```

회신이 필요 없는 강한 스킵 규칙은 root를 `*[문자수신]* :완료:`로 남긴다.
SMS 발신 성공은 같은 thread에 `:완료: SMS …`를 남긴다. 사람은 수신 root의
thread에 답장하면 같은 번호로 SMS를 보내며, 새 발신은
`!sms <전화번호> <내용>`을 사용한다.
